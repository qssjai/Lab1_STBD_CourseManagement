## Про проєкт

Це база даних для платформи з онлайн-курсами на PostgreSQL і невеликий консольний застосунок на C# (.NET 8), який з нею працює. У застосунку використано патерни Repository і Unit of Work.

У системі є користувачі з ролями (студент, викладач, адміністратор), курси з модулями та уроками, записи студентів на курси, платежі, завдання, тести, відгуки і сертифікати.

## Що зроблено

- Схема бази даних на 20 таблиць із зв'язками, ключами та обмеженнями. Діаграма лежить у папці Schema.
- Soft delete для користувачів, курсів, модулів, уроків і завдань. Записи не видаляються фізично, а позначаються полями is_deleted, deleted_at, deleted_by. Звичайний DELETE для цих таблиць заборонено тригером.
- Дата й автор останньої зміни (created_at, created_by, updated_at, updated_by) у таблицях users, courses, lessons, submissions і reviews. Усі зміни також потрапляють у таблицю audit_log зі старими та новими значеннями.
- 11 представлень, 8 функцій, 18 збережених процедур і 32 тригери.
- Індекси чотирьох видів: B-tree, partial, GIN і BRIN. У файлі 08_demo.sql є запити з EXPLAIN ANALYZE до й після створення індексів.
- Застосунок на C#, де читання йде тільки з представлень, а запис тільки через збережені процедури.

## SQL-скрипти

Запускати треба по черзі, у базі course_management:

- 01_schema.sql створює таблиці, ключі та обмеження. Скрипт очищає схему public, тому запускати його варто тільки на порожній навчальній базі.
- 02_indexes.sql створює індекси.
- 03_views.sql створює основні представлення.
- 04_functions.sql додає функції.
- 05_triggers.sql додає тригери для аудиту, soft delete та перевірки бізнес-правил.
- 06_procedures.sql додає збережені процедури.
- 07_seed.sql наповнює базу тестовими даними. Виконувати його треба один раз.
- 08_demo.sql містить демонстраційні запити, перевірки правил і EXPLAIN ANALYZE.
- 09_lookup_views.sql створює представлення довідників, які потрібні застосунку.

## Як запустити

Потрібні PostgreSQL 14 або новіший, .NET 8 SDK і Visual Studio 2022.

1. Створіть базу даних course_management. Це можна зробити в pgAdmin або командою `psql -U postgres -c "CREATE DATABASE course_management;"`.
2. Виконайте SQL-скрипти з папки Database по черзі, від 01 до 09. У pgAdmin відкрийте скрипт у Query Tool і натисніть F5. З терміналу це виглядає так: `psql -U postgres -d course_management -f Database/01_schema.sql`.
3. Відкрийте CourseManagement.sln у Visual Studio.
4. У файлі CourseManagement/Program.cs замініть YOUR_PASSWORD на пароль користувача postgres.
5. Запустіть проєкт через Ctrl+F5.

## Як база знає, хто змінив запис

Усі підключення до бази йдуть від одного користувача postgres, тому сама база не знає, хто саме з користувачів системи виконав дію. Щоб це вирішити, застосунок на початку транзакції передає в базу id користувача через set_config('app.current_user_id', ...), що працює так само, як SET LOCAL. Збережені процедури роблять те саме через функцію fn_set_actor. Тригери читають це значення функцією fn_current_user_id() і записують його в created_by, updated_by, deleted_by та audit_log.

## Що робить застосунок

Після запуску консоль по черзі показує чотири сценарії:

1. Створення курсу з модулями й уроками в одній транзакції.
2. Запис студента на курс, оплата, проходження всіх уроків і видача сертифіката.
3. Помилка посеред транзакції (публікація курсу без уроків) і відкат усіх змін.
4. М'яке видалення курсу разом з його модулями та уроками.

Клас UnitOfWork тримає одне з'єднання і одну транзакцію для всіх репозиторіїв, тому зміни фіксуються або скасовуються разом. Репозиторії: LookupRepository, UserRepository, CourseRepository (курси, модулі, уроки) і EnrollmentRepository (записи, платежі, прогрес, сертифікати).
